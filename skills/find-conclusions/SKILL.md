# 找结论：从一堆数字里挑出 3–5 句能写进汇报的话

汇报的听众记不住二十个数字，只记得住三五句话。这一步的任务是从表里找出最值得讲的那几句，并且保证每一句都经得起追问。

## 开始前先确认
- 听众是谁、最关心什么（如果 `report-flow` 已经问过，直接沿用）
- 数据已经体检过；没有的话，先跑 `data-checkup` 或至少检查漏月和重复行

## 怎么找：五个方向各看一遍
用代码算（pandas），不要心算或估计。每算一个数，就把公式记进「计算底稿」。

| 方向 | 看什么 | 常见结论长什么样 |
| --- | --- | --- |
| 总量 | 全年合计 vs 目标、vs 去年 | 「全年销售额 1,280 万，完成目标的 107%」 |
| 趋势 | 哪个月开始变好 / 变差，拐点在哪 | 「下半年月均比上半年高 31%，拐点在 7 月」 |
| 结构 | 占比怎么变了（产品、渠道、客户） | 「新客户贡献从 18% 升到 35%」 |
| 效率 | 人均、单位成本、转化率 | 「每获取一个客户的成本降了 22%」 |
| 异常 | 特别好或特别差的单月 / 单项 | 「11 月单月下滑 40%，原因【待你补充】」 |

## 每条结论的格式
```
结论 N：一句话（主语 + 变化 + 数字），不超过 25 个字
- 数字：1,280 万（全年销售额合计）
- 对比：目标 1,200 万 → 完成 107%；去年 1,050 万 → 增长 22%
- 出处：《年度业绩表》第 2–13 行「销售额」列求和；增长率 =(1280−1050)/1050
- 确定程度：确定 / 待确认（说明缺什么）
- 对听众意味着什么：一句话，用听众关心的语言
```

## 选哪 3–5 条
1. 先排序：和听众最关心的事越相关、变化幅度越大、越确定，越靠前
2. **至少留一条坏消息或风险**，并配上「打算怎么办」。藏起来的坏消息，老板最容易问到；主动讲出来，反而显得心里有数
3. 两条结论说的是同一件事，就合并

## 不要做的事
- 不编原因。数据只能说明「发生了什么」，「为什么」要问用户，写成【待你补充：…】
- 不挑数据。只选对自己有利的时间段或口径，被追问时最难圆；口径和时间范围在出处里写清楚
- 不报假精确。原始数据是整数，就别算出小数点后三位；百分比一般保留到整数

## 交付
1. 结论清单（3–5 条，按上面格式）
2. 计算底稿：每个数字的计算代码或公式，方便用户自己核对
3. 一句话总结：把最重要的那条结论再压缩成一句，留给 `story-builder` 当第一页
