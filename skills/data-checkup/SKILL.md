# 数据体检：先确认表没问题，再谈结论

一整年的数据通常是好几张表拼起来的。漏掉一个月，全年合计就少了；重复一行，增长率就虚高；中途从「元」改成「万元」，图上就会凭空出现一个断崖。这些错放进 PPT，被老板一眼看出来，后面讲得再好也没用。

## 怎么做
1. **先跑脚本**（不用自己写检查逻辑）：
   ```bash
   python scripts/checkup.py <表格路径> [--date-col 列名] [--key-cols 列1,列2] [--out 体检报告.md]
   ```
   支持 .csv / .xlsx / .xls。不指定 `--date-col` 时脚本会自己猜日期列。脚本只读不改，输出一份 Markdown 体检报告。
2. **读报告，按影响排序讲给用户**：先讲会让合计或增长率算错的（漏月、重复、单位突变），再讲只影响个别数字的（空值、异常值）。
3. **每个问题给一个建议处理方式，并说明理由**，例如：
   - 漏月：问用户是「真的没有业务」还是「导出时漏了」；前者填 0 并在汇报里说明，后者请他补数据
   - 重复行：列出重复的几行，建议保留一行；但如果是同一天两笔真实交易，就不是重复
   - 单位突变：指出从哪个月开始数量级变了约多少倍，问是不是换了单位
   - 异常值：列出来问原因，有原因的异常往往就是故事里的「转折」
4. **等用户确认后再改**。改的时候另存一份新文件（例如 `原文件名_已清洗.csv`），并附一段「改了什么」的清单，原文件不动。

## 为什么不直接改
表里看起来异常的地方，很多是业务事实：某月停业、一次大客户签约、组织调整。直接「修正」会把最有价值的信息抹掉。体检的任务是让用户知道哪里有问题，决定权在他。

## 输出格式
```
## 体检结论：发现 N 个问题，其中 M 个会影响合计或增长率
| 严重程度 | 问题 | 在哪里 | 建议怎么处理 |
...
## 需要你确认的 K 件事
1. ……
```
