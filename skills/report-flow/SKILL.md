# 汇报总控：从一张表到一份讲得清、抗得住的汇报

这个 skill 负责把整件事串起来。它本身不做细活，细活交给同仓库的另外 4 个 skill：
`data-checkup`（数据体检）→ `find-conclusions`（找结论）→ `story-builder`（讲成故事）→ `boss-grill`（模拟质询）。
没装那几个也能用：每一步下面都写了最少要做到什么。

## 为什么要先问再做
同一张表，讲给财务总监和讲给业务老板，是两个故事。不问听众就开工，产出的往往是一份「什么都说了、谁都没打动」的汇报。所以第一步永远是问清楚，问完再碰数据。

## 第 0 步：问三个问题（一次问完，用户答不上的给默认值）
1. **讲给谁听**：直属领导 / 部门负责人 / 老板 / 跨部门？（默认：直属领导）
2. **他最关心什么**：业绩增长 / 成本 / 项目交付 / 团队成长？（默认：业绩增长）
3. **讲多久、几页**：5 分钟 5 页 / 15 分钟 10 页？（默认：5 页）

另外问一句：这一年里有没有一件你自己觉得最值得讲的事？用户的真实经历是故事里「转折」那页最好的材料，AI 不能替他编。

## 第 1 步：数据体检（用 `data-checkup`）
最少要做到：查出漏掉的月份、重复的行、空值、前后口径或单位不一致的列。**先列问题，等用户确认再改**，因为有些「异常」是业务事实（比如某月真的停业）。

## 第 2 步：找结论（用 `find-conclusions`）
最少要做到：3–5 条结论，每条有一个数字、一个对比基线（去年 / 目标 / 上半年），并写明这个数是怎么算出来的。好消息和坏消息都要找，汇报里藏起来的坏消息，老板最容易问到。

## 第 3 步：讲成故事（用 `story-builder`）
最少要做到：按「一句话结论 → 基线 → 转折 → 洞察 → 明年怎么做」排页；每页标题是一句观点，不是「Q3 数据」这种主题词；百分比翻译成听众关心的话。

## 第 4 步：模拟质询（用 `boss-grill`）
最少要做到：站在第 0 步那位听众的角度，提 5 个最可能被问的问题，并给出答题要点。用户想练的话，就一问一答地练。

## 交付物
按顺序给用户：
1. 体检报告（问题清单 + 建议怎么处理）
2. 结论清单（每条带出处）
3. 汇报大纲（每页：标题、要讲的一句话、配什么图、数字出处、讲稿）
4. 追问清单（问题 + 答题要点）

用户要 PPT 时，把大纲交给能做幻灯片的工具；用户只要大纲，就停在第 3 份。

## 贯穿全程的三条规矩
- **数字可追溯**：每个出现在结论和 PPT 里的数字，都能指回原表的哪几行、哪一列、什么公式。算数一律用代码算，不心算。
- **不编**：数据里没有的原因、经历、背景，用「【待你补充：…】」标出来问用户，不替他想象。
- **示意数据要标注**：如果用的是示例或虚构数据，图和表上写「示意数据」。
