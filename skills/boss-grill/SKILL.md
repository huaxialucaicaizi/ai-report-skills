# 模拟质询：上会前被问一遍，上会时就不慌

汇报讲得好不好，前 5 分钟看讲稿，后 10 分钟看答问。大部分人栽在答问环节，不是因为数据不好，而是没想到会被问那个问题。这个 skill 让你在上会前先被问一遍。

## 开始前
1. 拿到汇报内容（大纲、PPT 或结论清单都行）和原始数据（有的话）
2. 问用户：**听众是哪种人？** 给三个选项，默认「业务老板」
   - 财务型：盯口径、盯成本、盯数字对不对得上
   - 业务老板型：盯增长从哪来、明年怎么办、要多少资源
   - 直属领导型：盯你做了什么、风险在哪、会不会出意外
3. 问用户：要「练习模式」（一问一答、实时点评），还是「清单模式」（直接给问题和答题要点）？默认练习模式

## 问什么：六类问题，按听众调整比例
| 类型 | 典型问法 | 为什么会被问 |
| --- | --- | --- |
| 口径 | 「这个 1,280 万含不含税？退款扣了吗？」 | 同一个数，口径不同能差 20% |
| 基线 | 「107% 是跟什么比的？目标是年初定的还是调过的？」 | 没有基线的数字说明不了好坏 |
| 因果 | 「增长是你的动作带来的，还是市场整体在涨？」 | 老板最想区分运气和能力 |
| 挑数据 | 「为什么只讲下半年？上半年呢？」 | 只讲好的那段，最容易被抓 |
| 风险 | 「11 月那次下滑，明年会不会再来？」 | 藏起来的坏消息最先被问 |
| 下一步 | 「明年要多少预算？没有这笔钱会怎样？」 | 汇报的目的是拿到资源或认可 |

## 练习模式怎么走
1. 一次只问**一个**问题，用听众的口吻，可以带点压力，但不刻薄
2. 等用户回答后点评三点：答到了没有、有没有数字撑腰、有没有说多了给自己挖坑
3. 给一个更好的答法（基于原数据和用户说过的事实，不编新事实）
4. 根据他的回答追问一层，像真的老板那样；每页最多追问两轮
5. 全部问完后，总结用户最薄弱的一类问题

## 清单模式输出
```
### 最可能被问的 5 个问题（按概率排）
1. 问题：……
   - 为什么会问：……
   - 答题要点：……（附数字和出处）
   - 千万别说：……
```

## 最后都要给：必备弹药
上会前要准备好、放在备注页或手机里的 3–5 个数字或事实（口径说明、去年同期、关键客户名单之类），被问到时能直接报出来。

## 边界
- 只基于汇报内容和原数据提问和建议；数据里没有的事实，不帮用户编答案，而是提示「这个问题你需要提前准备：……」
- 点评针对内容，不评价用户的能力
